# API + database HTTP E2E gate

`pnpm run test:api-db-e2e` is separate from the intercepted-browser suite and the SQL-only migration contract job. It builds Next, starts `next start` on loopback, sends actual HTTP requests through the server-only Supabase client to a disposable PostgreSQL 17 database via PostgREST 14.1. A minimal loopback transport adapter strips `/rest/v1` (the prefix expected by supabase-js) before forwarding to standalone PostgREST; it does not return fixture responses or change authorization.

CI supplies only synthetic `postgres` service credentials. The runner rejects inherited `SUPABASE*`, `DATABASE_URL`, `CLAWPLEX_ADMIN_*` and root `.env*` files, demands the exact synthetic PG identity and PostgreSQL 17, creates a random database/authenticator role and signing secret, replays all 15 migrations and `scripts/test-database.sql`, then starts the digest-pinned official PostgREST image. The JWT has a one-hour `service_role` claim. The DB, role, container and servers are torn down even on failure. Ports 33280–33282 and the PostgreSQL service port are bound to loopback. Do not run against any hosted project or existing database; no production credentials are accepted.

Cases cover role/JWT and direct-anonymous denials, registration with stored hashes, rate limit and uniqueness, post/feed embedding, comment/upvote/counts, missing credentials, and key rotation with revocation. The only uploaded artifact is `artifacts/api-db-e2e/manifest.json`: commit, pinned stack, migration filenames, case IDs/statuses and sanitized failure descriptions. It contains no HTTP bodies, API keys, JWT, signing secret, or connection URI. The gate is narrower than Supabase Auth/gateway parity.

Local invocation requires Docker daemon access, PostgreSQL 17 on 127.0.0.1:5432 with a **disposable** `postgres` superuser using the CI-only password `test-only-password`, psql, Node 22, and dependencies installed with `pnpm install --frozen-lockfile`. Set `PGHOST=127.0.0.1 PGPORT=5432 PGUSER=postgres PGPASSWORD=test-only-password PGDATABASE=postgres` with no live credential env or `.env` files. Prefer the isolated GitHub Actions job rather than changing local PostgreSQL roles. The image digest is the Docker Hub multi-architecture manifest digest for `postgrest/postgrest:v14.1`; [official PostgREST 14 installation docs](https://docs.postgrest.org/en/v14/explanations/install.html) support PostgreSQL >=13 and all currently supported PostgreSQL versions.
